# Output with ALV (SAP List Viewer)

- **[P2]** Classic lists in productive programs are obsolete — use ALV (SAP List Viewer) instead (ABAPDocu: "Classic lists should no longer be used in live application programs. Use SAP List Viewer (ALV) instead of classic lists.").
- **[P3]** If a classic list stays for legacy, avoid the obsolete constructs in it: obsolete formatting, obsolete calculations, obsolete list events and obsolete spooling (ABAPDocu: obsolete statements in list processing).
- **[info]** ALV stack: for read-only simple lists — the SALV model (`cl_salv_table` factory, no manual field catalog); for interactive/full-grid features — `cl_gui_alv_grid` in a container. Container choice: `cl_gui_custom_container` (dominant — a custom screen area), `cl_gui_docking_container` (docking panel, no custom screen), `cl_gui_splitter_container` (several ALVs side by side). SAP GUI technology, prepares a dynpro screen.
- **[P2]** Legacy FM-ALV — `REUSE_ALV_GRID_DISPLAY`/`REUSE_ALV_LIST_DISPLAY` + the `slis_*` stack (`slis_t_fieldcat_alv`, `slis_layout_alv`, `slis_selfield`, `slis_t_event`, `REUSE_ALV_FIELDCATALOG_MERGE`): still ALV, but an obsolete FM pattern. Do not create new FM-ALV — use SALV/grid; it is not the same as a classic `WRITE` list.
- **[P3]** SALV events — `get_event( )` → `cl_salv_events_table`, handlers `on_user_command`/`on_double_click`. Both SALV and grid register handlers the same way — `SET HANDLER` on the event source instance (see the grid rule below); the SALV difference is only that the handlers come from `cl_salv_events_table` instead of being declared for `cl_gui_alv_grid`.
- **[P2]** Editable grid: mark editable columns via `lvc_s_fcat-edit`, `register_edit_event( )`, then validate in `check_changed_data( )` — do not read the grid cells directly for validation.
- **[P3]** Selection — grid `get_selected_rows( )`/`get_selections( )` + `set_selection_mode( )`; do not track the current row manually.
- **[P3]** Hotspot/clickable cells — SALV `set_cell_type( if_salv_c_cell_type=>hotspot )`, grid field `lvc_s_fcat-hotspot`.
- **[info]** Grid GUI status/title — `SET PF-STATUS`/`SET TITLEBAR`; grid callback `i_callback_pf_status_set` (legacy) or `SET HANDLER ... user_command` (OO).
- **[P3]** Manual column-text overrides (`coltext`/`scrtext_l/m/s`/`outputlen`) are pervasive — when a DDIC label does not fit, centralize overrides in one field-catalog builder, not scattered per screen.
- **[P3]** Derive the output columns from the output structure (SALV columns / `lvc_s_fcat` from the DDIC type) instead of a hand-built field list and hand-set column texts — dictionary texts (data element labels) are the single source.
- **[P3]** Screen preparation is part of PBO/dialog: build the output data and the ALV control in a class method, not inline in the module (see `style.md`, "Screens and events"). ALV events (toolbar, double-click, buttons) — in separate event-handler classes with injected dependencies, no business logic in the event blocks (see `classes.md`).
- **[P3]** Accessibility (see `style.md`): column headers via dictionary texts, enough label/short text, no color-only marks; respect variant/layout support where the team relies on it.
- **[P2]** SALV errors/exceptions — class-based (`cx_salv_msg`/`cx_salv_error`); handle them, do not swallow (`errors.md`: an empty `CATCH` is forbidden).
- **[P2]** Layout variants: give the layout a key — SALV `get_layout( )->set_key( )` / grid via the `set_table_for_first_display` params `is_variant` (type `disvariant`, `report = sy-repid`) + `i_save` (e.g. `'A'`); `lvc_s_layo` has no `vari` field. Do not weaken `save_restriction` without the team's say: saved variants are the user's work, destroy them only deliberately.
- **[P3]** Sorting/totals — display-level: SALV `get_sorts( )->add_sort( )` / `get_aggregations( )->add_aggregation( columnname = ... )` (grid — sorting via `lvc_t_sort`; totals via field-catalog `do_sum` / sort `subtot`, the grid has no aggregation-table *parameter* unlike SALV) instead of pre-sorting the internal table just for the ALV.
- **[P3]** Grid events (double-click, toolbar, F4, edit) — OO grid subscribes directly via `SET HANDLER handler->on_double_click FOR grid` (where `grid` is the grid instance), not `FOR EVENT ... OF cl_gui_alv_grid` — `FOR EVENT` belongs to the **METHODS** declaration of the handler, not to the registration: `METHODS on_double_click FOR EVENT double_click OF cl_gui_alv_grid.` + `SET HANDLER handler->on_double_click FOR grid`; `set_registered_events` is only for `cl_gui_alv_tree`/`cl_gui_toolbar`. Legacy grid — callbacks `i_callback_user_command`/`i_callback_pf_status_set`. Input validation lives in the event handler, not in business methods; for editable cells the grid needs `set_ready_for_input( )` in PBO after `set_table_for_first_display( )`.
