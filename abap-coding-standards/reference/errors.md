# Error handling

- **[P2]** Class-based exceptions (`CX_*`), not classic `RAISE`.
- **[P1]** Do not catch a broad `CATCH cx_root`/`cx_sy_*`-base — it swallows everything, including `CX_NO_CHECK`/system ones. Catch a concrete `zcx_*`/`cx_*` and wrap it (see below); if `CATCH cx_root` is unavoidable — re-raise or log, do not swallow. <!-- rule: no-broad-catch -->
- **[P3]** One base exception class per package; raise one type; subclasses — only so the caller can distinguish cases.
- **[P2]** Exceptions — for errors, not for regular cases (Clean ABAP): a valid, expected outcome is a regular result (`RETURNING` value/status), not an exception — otherwise call sites are noisy and the real results are hidden. Do not model expected cases (a toggle, "already exists", optional "not found") as exceptions where the caller is supposed to handle them as normal.
- **[info]** abapGit: an exception class (descendant of `CX_*`) in `.clas.xml` requires `<CATEGORY>40</CATEGORY>` (a normal class — 0); without it, it is created as a normal class (activation does not fail).
- **[info]** `CX_STATIC_CHECK` — expected (to propagate, declare in `RAISING`); `CX_DYNAMIC_CHECK` — avoidable, the caller checked preconditions (also `RAISING`, but the declaration check is at runtime); `CX_NO_CHECK` — system, no `RAISING` needed, always propagates (you can still `CATCH` it).
- **[P0]** Unrecoverable — cannot continue: stop processing and do not commit. Mechanism — by application type: `RAISE` up to the top level (there → message/HTTP 500), or log + abort. "Swallowed and moved on" — not allowed. <!-- rule: unrecoverable-no-commit -->
- **[P1]** Do not use `ASSERT` for business/invariant checks: it aborts the program with a dump, is meant for assumptions (and even with `ID`/`FIELDS` a *violated* assertion still aborts), and active assertions cannot be handled/relogged like class-based exceptions. Integrity/impossible-state checks — only `IF … RAISE` with a clear text, or explicit error handling. (Only `ASSERT … ID` can be deactivated via a checkpoint group / SAAB — an `ASSERT` without `ID` is always active and cannot be switched off.) <!-- rule: no-assert-for-business -->
- **[info]** `RAISE EXCEPTION`: `TYPE class` — empty; `TYPE class MESSAGE ...` — from a message; `NEW class( ... )` — with constructor parameters; a reference variable — an already-created one. A functional call after `RAISE EXCEPTION` (`RAISE EXCEPTION zcx_x=>factory( )`) is invalid — first `DATA(lx_err)`, then `RAISE EXCEPTION lx_err`. `RAISE EXCEPTION NEW ...` — only from 7.52, do not use in 7.50.
- **[info]** `MESSAGE ID sy-msgid TYPE sy-msgty NUMBER sy-msgno WITH ...` (dynamic message) requires the exception class to implement `IF_T100_DYN_MSG`; a static `MESSAGE eNNN(class)` needs only `IF_T100_MESSAGE`. `WITH` fills `msgv1..4` only with `IF_T100_DYN_MSG`. To move an `IF_T100` exception's message into `sy-msg*` — `cl_message_helper=>set_msg_vars_for_if_t100_msg( text = lx_exc )` (the importing parameter is `text`, not `io_exception` — a named `io_exception` does not compile; a positional `set_msg_vars_for_if_t100_msg( lx_exc )` also works).
- **[info]** Exception class constructor: `previous TYPE REF TO cx_root OPTIONAL` (copy the signature only into a `CX_ROOT` descendant; the `!` before a parameter is cosmetic — do not write it by hand).
- **[P2]** Wrap others' exceptions (`cx_reca_symsg` and other `cx_*` of external components) in your own `zcx_*` — do not let them leak into your code.
- **[P3]** Handle an exception as close as possible to where it is raised — at the level whose context already has enough information. Neither propagate deeper than needed nor catch early without a purpose: an early catch followed by a re-raise is noise, an early catch that swallows is a defect (see the empty-catch rule below).
- **[P2]** Fail fast: check preconditions at the start of the method.
- **[P2]** Write under a lock: `ENQUEUE_*` (enqueue server, not a DB lock) + check (`foreign_lock`); `DEQUEUE_*` at the end, in all branches, including `CLEANUP`. Generated `ENQUEUE_*` FMs take the parameters `_scope` (lock scope), `_wait` (block on a foreign lock instead of returning `foreign_lock`) and `_collect` (collect-mode locking).
- **[P2]** HR OM/PA — via classes: `set_exclusive_lock`/`remove_exclusive_lock`; release locks on **every** path — success, error and especially in `CLEANUP` (CLEANUP does not run on the normal success path or after a `CATCH` already handled the error — release explicitly on each branch). Write — trial pattern: `start_trial` → `approve_trial`+`flush(no_commit=abap_false)` / `discard_trial` in `CATCH`. (Interface `if_hrpa_masterdata`, class `cl_hrpa_masterdata`.)
- **[P1]** Check the result of a call with a status (`sy-subrc`, an HR FM's return structure, `et_message`, `ev_success`) immediately, before other calls/assignments: the next call overwrites the previous result → an error looks like success. Do not consider an operation successful until all checks pass. Good: `CALL FUNCTION 'FM' ... . IF sy-subrc <> 0. ... RETURN. ENDIF.` Bad: another statement (`CLEAR`, a second call) between the call and the `IF sy-subrc`. <!-- rule: check-subrc-immediately -->
- **[P2]** Calling legacy FMs: the same "check right after the call" rule (previous bullet) — the result is `sy-subrc` (classic FMs) or the BAPI return table (`BAPIRET2`/`et_return`/`et_message`); handle the declared classic `EXCEPTIONS ...` (a non-handled `subrc` is a **silent** failure, not an automatic error); a blanket `EXCEPTIONS OTHERS = n` that discards every exception is the classic-FM analog of an empty `CATCH` — handle the named exceptions, do not swallow `OTHERS` blindly. `TABLES` parameters of a classic FM are passed **by reference** — the FM can modify the caller's table without declaring it; copy the table at the call site if it must not change. Wrap legacy FM calls in a class method so the check and the error handling are in one place (see `classes.md`).
- **[P2]** `SUBMIT ... AND RETURN` returns no result/error, `sy-subrc` after `SUBMIT` is unreliable: do not consider an operation successful from the `SUBMIT` return. Check the fact of the write afterwards (`READ`/`SELECT`) or use an FM/class with an explicit status.
- **[P2]** RFC: handle the predefined exceptions `SYSTEM_FAILURE`/`COMMUNICATION_FAILURE` — an unhandled network/system error silently leaves the operation incomplete (details — `integration.md` "Remote communication"; parallel tasks — `parallel.md`).
- **[P2]** One logical operation = one `COMMIT WORK` at the end, after all checks. COMMIT "in chunks" — only in mass loading. (Splitting an LUW into independent `COMMIT`s — P1, see SKILL.md "Exception to downgrade".) `BAPI_TRANSACTION_COMMIT`/`BAPI_TRANSACTION_ROLLBACK` are the BAPI-layer equivalents — `BAPI_TRANSACTION_COMMIT` ≈ `COMMIT WORK AND WAIT` **only with `WAIT = 'X'`** (the FM then defers the return until the V1 update of the LUW is complete); without `WAIT = 'X'` it behaves like plain `COMMIT WORK` — do not read back the written data or notify until the update has actually finished.
- **[P2]** User messages — only via message class SE91 (class/number as literals — otherwise where-used in SE91 disappears) or text elements `TEXT-xxx`; not a literal. Message parameters — `&1..&4`.
- **[info]** If message attributes are passed implicitly (variables `sy-msgid`/`sy-msgno`/…, e.g. from an exception), keep a static anchor so the message stays in the where-used list: `IF 1 = 2. MESSAGE e123(abc) INTO sy-msgli. ENDIF.` (class/number as literals, see above) — then the message class/number is discoverable from SE91.
- **[P1]** An empty `CATCH` (immediately `ENDTRY`) is forbidden — swallowing an error: handle the exception or do not catch at all. <!-- rule: empty-catch-forbidden -->

# Update task and V1/V2

- **[P2]** Deferred write: `CALL FUNCTION ... IN UPDATE TASK` — the FM runs in an update work process at `COMMIT WORK`. `SET UPDATE TASK LOCAL` switches only **V1** update modules into the current work process/DB LUW and executes them synchronously at `COMMIT` (regardless of `AND WAIT`; `sy-subrc` 0 — activated, 1 — not activated: an FM already registered for a normal update); **V2 modules are ignored** by the local mode. Do not use it "to await the write" — it changes where and how the update runs, not an alternative to `AND WAIT`.
- **[P2]** V1 (critical) / V2 (secondary: statistics, indexes, background) — set by the update FM's **attributes** (`V1`/`V2` in the update module), not by `PERFORM ... ON COMMIT` (that is a **separate** older mechanism — the deferred code runs in the same work process at commit, no V1/V2 semantics). A V1 error → V2 does not run, the **update-task DB LUW** rolls back (the caller's already-committed direct writes remain); a V2 error → V1 is already committed.
- **[P2]** `COMMIT WORK AND WAIT` — synchronous: waits for **V1** update tasks to complete, `sy-subrc` shows their result; without `AND WAIT` update tasks run asynchronously, the result is not visible. (V2 runs later and is not awaited by `AND WAIT`.) Need the write result — `AND WAIT` (in dialog — delay; if the status is not needed, `COMMIT WORK` without `AND WAIT` is faster).
- **[P1]** An update FM must not commit itself: inside an update task `COMMIT WORK`/`ROLLBACK WORK` are forbidden (terminates the task). The whole transaction commits with the caller's single `COMMIT WORK`. <!-- rule: update-fm-no-self-commit -->
- **[info]** bgRFC (`CALL FUNCTION ... IN BACKGROUND UNIT ...`) — transactional/queued deferred processing, a sibling of the update task: executes exactly once after the creating LUW's `COMMIT WORK`, with queue/retry semantics. Mechanics and API — `parallel.md` "bgRFC".

# Resumable exceptions

- **[info]** `RAISE RESUMABLE EXCEPTION ...` — the caller can `CATCH ... BEFORE UNWIND` and continue via `RESUME` (execution continues *after* the `RAISE`). A method that may raise a resumable exception declares it in the signature as `RAISING RESUMABLE( zcx_... )` (distinct from the `RAISE RESUMABLE EXCEPTION` statement). `RETRY` — allowed in a normal `CATCH`: re-runs the whole `TRY` block from the start. Do not confuse them: `RETRY` repeats the block, `RESUME` continues after `RAISE` (and requires `BEFORE UNWIND`).
- **[P3]** Resumable — for "try again/substitute a value", not for normal errors: a normal error — a normal exception.
- **[P2]** `CATCH ... BEFORE UNWIND` is more expensive than a normal `CATCH` (does not unwind the stack, keeps context) — use deliberately, not by default.
