# HR — PA write path

> Release: the 7.50 API of the PA framework (`cl_hrpa_*`). The read side and the framework entry points — `hr-pa.md`.
> Writing PA master data: trial/flush, containers, locks, messages, and everything a write pulls in (time constraints, OM sync, retrocalc, BAdI checks).

## Write path — trial and container

- **[P2]** Write layer entry point — `cl_hrpa_masterdata_bl=>get_instance( IMPORTING masterdata_buffer OPTIONAL EXPORTING masterdata_bl TYPE REF TO if_hrpa_masterdata_bl )` (declared `RAISING cx_hrpa_violated_assertion` — call it inside a `TRY`); the factory equivalent is `get_business_logic( )` (same object; raises `cx_hrpa_violated_precondition` if the factory was initialized in legacy mode). Data methods (`if_hrpa_masterdata_bl`): `read` / `insert` / `modify` / `delete` / `action` / `get_infty_container` / `regroup`; buffer control (`if_hrpa_buffer_control`): `start_trial` / `approve_trial` / `discard_trial` / `initialize` / `flush`.

- **[P1]** PA write path — one group of records = one trial: `start_trial( IMPORTING magic_cookie TYPE REF TO if_hrpa_token )` → `read` / `get_infty_container` → `modify_primary_record` → `insert` / `modify`; on success `approve_trial( magic_cookie )` + `flush( no_commit = abap_false )`, on any failure `discard_trial( magic_cookie )` before returning. `flush( no_commit = abap_false )` commits the whole group with one `COMMIT WORK`; without `no_commit` the buffer is written without a commit — no partially written group, no per-record commits. <!-- rule: hrpa-bl-trial -->

- **[P1]** A started trial must be closed on **every** path, including a failed `flush`: a skipped `discard_trial` leaves a level on the write-buffer stack and every later `flush` fails with `cx_hrpa_invalid_buffer_stack` (`stack_not_empty`) for the rest of the session. After `approve_trial` the cookie is consumed — resetting that path means `initialize( )` (it also drops the read buffer and pending OM data). The PD layer does the same under its own names: `if_hrbas_dispatch_bl~flush` raises `cx_hrbas_invalid_buffer_stack` with `textid = cx_hrbas_invalid_buffer_stack=>cx_hrbas_stack_not_empty` while the cookie stack is not empty, and the PD admin `flush( )` does **not** close a trial — it only delegates to the dispatch BL, so `flush` before `approve_trial`/`discard_trial` fails. <!-- rule: hrpa-bl-trial-close -->

- **[P1]** PA container write path — a container handed to `if_hrpa_masterdata_bl~modify` must be the one **read from the buffer**, never one built from your own payload. <!-- rule: hrpa-container-modify-from-buffer -->
  - **What breaks:** `cl_hrpa_data_sharing~modify` compares `container->grouping_value( )` with `old_container->grouping_value( )` after the ALE check and raises `cx_hrpa_invalid_parameter` (`parameter = 'CONTAINER'`) on any difference (the same check runs after the time-constraint step). The in-code comment says it outright: "A container which is to be modified must be read from the buffer. It must not be created. Newly created containers can only be inserted."
  - **Why a hand-built record loses the value:** `grouping_value( )` is `a_pshd1-grpvl`, and `if_hrpa_infty_container_data~modify_primary_record` takes the **whole PSHD1 from the passed record**, preserving only `itxex`/`refex`. A record built outside PA (`cl_hr_pnnnn_type_cast=>prelp_to_pnnnn` over a `PRELP` without `GRPVL`; `GRPVL` lives in `PRELP`/`PSHD1` and in the `paxxxx` tables) therefore wipes the grouping value — `modify` of an existing key fails, while `insert` passes: a new key gets it from the framework (`set_grouping_value( a_grouping_reader->c_gpval_ungrouped )`) and has no old container to compare against.
  - **Fix:** carry the header over before `modify_primary_record` — `ASSIGN <ls_pnnnn> TO <ls_pshdr> TYPE pshdr CASTING.` then `<ls_pshdr>-pshd1 = lo_old->pshd1( ).` (the `PSHD1` getter sits on `if_hrpa_infty_container`, aliased in `cl_hrpa_infotype_container`; the framework casts `pnnnn` to `pshdr` itself) — or `set_grouping_value( old_container->grouping_value( ) )` (`if_hrpa_infty_container_group`).
  - **Catch the standard ancestor:** `cx_hrpa_invalid_parameter` → `cx_hrpa_violated_precondition` → `cx_hrpa_violated_assertion` → `cx_dynamic_check`, so a `CATCH` naming a project wrapper that itself **inherits** from the standard class catches nothing, and the session ends in `UNCAUGHT_EXCEPTION`.


## Locks and messages

- **[P2]** Locks — `cl_hrpa_masterdata_enq_deq` (static) `enqueue_by_pernr( EXPORTING tclas = cl_hrpa_tclas=>tclas_employee pernr message_handler IMPORTING is_ok locking_user )` / `dequeue_by_pernr( EXPORTING tclas pernr )`. Asymmetric: only enqueue returns a status and fills the handler — every `is_ok = false` branch writes an E message (e.g. `PBAS_SERVICE 014` with the locking user), so the row error comes from the handler, not from `sy-msg*`; `dequeue_by_pernr` declares neither `is_ok` nor `message_handler`, a failed unlock shows only as a `CATCH`. Enqueue also locks the connected objects (the CP and the pernrs of 0322/0021) and registers in `HR_DEQUEUE_REGISTER` — not a cheap one-object lock. Both raise `cx_hrpa_violated_assertion` (incl. `cx_hrpa_invalid_parameter` for `pernr = '0'`, `cx_hrpa_missing_lock` when promoting a lock not requested as promotable).

- **[P2]** HR messages — `cl_hrpa_message_list` (instantiate with `NEW`, no factory — unlike `cf_reca_message_list=>create`), producer interface `if_hrpa_message_handler`. `get_message_list`/`get_error_list`/`get_abend_list`/`has_error`/`has_abend`/`add_messages` are all declared `RAISING cx_hrpa_violated_assertion` — keep every call inside a `TRY`. Same accumulate/query pattern as `cl_reca_message_list` — `logging.md`; row error by type — `get_error_list` (`msgty = 'E'`), then `get_abend_list` (`'A'`; `is_ok = false` may carry either), `get_message_list` — everything. Where the messages are deliberately not needed, the framework accepts `cl_hrpa_dummy_message_handler` (`create public`, `add_message` empty) instead of the real list — pass it knowingly: it discards every message.

- **[P2]** Framework ↔ your message format — wrap the handler you pass into `if_hrpa_masterdata_bl~*` instead of post-processing the list by hand: `cl_hrpa_message_struct_remap` (implements `if_hrpa_message_handler`, `set_remapping( structure_name )`), `cl_hrpa_message_generic_remap`, `cl_hrpa_message_fields_remap` (`initialize( )`/`extend_remapping( )`), `cl_hrpa_message_fields_preset`; `cl_hrpa_detail_messages` (constructor: your handler) is the detail-level filter (`max_detail_level = 9`).


## Around a write

- **[P2]** Container write: `get_infty_container( EXPORTING tclas pskey message_handler IMPORTING container is_ok )` — check `is_ok` (otherwise a cleared container propagates); the data goes in via `cl_hrpa_infotype_container->modify_primary_record( pnnnn )`, which returns `IF_HRPA_INFTY_CONTAINER_DATA` — downcast with `?=` (the specialized `cl_hrpa_it<nnnn>_container` inherit from `cl_hrpa_infotype_container`); the key of a freshly created container — `container->a_pskey`; then `insert` / `modify( old_container = <the container read by key> CHANGING container )`. The PD container class/template comes from the factory — `cl_hrbas_infotype_factory=>get_container_template( EXPORTING infty subty IMPORTING template )` (the container itself, no `CREATE OBJECT` by name) and `get_container_name( ... → seoclsname )`; `no_auth_check` — only where you verified authorization yourself (`security.md`).

- **[P2]** A broken framework precondition/postcondition (`cx_hrpa_violated_assertion` and its descendants) is turned into messages by `cl_hrpa_resolve_exception=>resolve( EXPORTING exception TYPE REF TO cx_hrpa_violated_assertion message_handler ) RAISING cx_hrpa_invalid_parameter` — resolve it at the boundary instead of letting it leak into the caller or swallowing it (`errors.md`).

- **[P2]** PA↔other objects on write — do not build your own sync: `cl_hrpa_om_integration=>enable_om_integration( )` (PA→OM; `cl_hrpa_masterdata_bl~flush` calls it as `post_flush`), `cl_hrpa_bp_integration` (statics — `activate_bp_integration`/`deactivate_bp_integration`, `check_bp_integration_necessary`, `is_record_relevant_for_bp_inte…`, `trigger_integration`, `suppress_integration_via_rfc`), `cl_hrpa_ale_handler`/`cl_hrpa_dummy_ale_handler` (`is_pernr_maintainable( tclas pernr message_handler )`, `flush( )`, `write_change_pointer( tclas infty subty pernr begda endda )` — the dummy suppresses change pointers for technical writes), `cl_hrpa_workflow_handler` (`get_instance`, `if_hrpa_workflow_handler`: `insert`/`update`/`delete` on a `prelp` + `flush( )`), `cl_hrpa_data_sharing=>trigger_regrouping( tclas infty pernr → infty_tab )`.

- **[P1]** HR writes and time constraints (PA infotypes 0000/0001/0002/…): a change is not a blind `UPDATE` of `pa000x` — the time-constraint logic decides how a new begin/end date inserts, delimits or overwrites existing records. TC1 — a single uninterrupted record (no gaps, no overlapping); TC2 — at most one record with gaps allowed (no overlapping); TC3 — several parallel records delimited by dates. Route writes through the mastered framework / with the trial pattern and a lock (see `errors.md`), never `MODIFY pa0001` — otherwise the record history gets gaps/overlaps (a P1 data-consistency defect, not just style). <!-- rule: hr-writes-time-constraints -->

- **[P3]** Do not copy ABAP-derived HR values (seniority, age, dated differences) into a PA infotype at runtime — they are recomputable from the master records; storing derived data that can drift from the source is a data-quality find.

- **[P2]** Your own checks for an infotype go through the BAdI, not by copying the standard class: `if_ex_hrpad00inftybl` / `if_ex_hrpad00inftydb` (BAdIs `HRPAD00INFTYBL`/`HRPAD00INFTYDB`) — `initialize( infotype_read_handler masterdata_buffer_handler molga_read_handler timeconstraint_handler masterdata_bl_handler … )` hands you the framework handlers, and the `*_computations` methods run **after** the standard checks (reference implementations: `cl_exm_im_hrpad00inftybl`, `cl_exm_im_hrpad00inftydb`). Check definitions for metadata — `cl_hrpa_foreign_key_check` (`initialize( )`, `add_foreign_keys( )`, `check_field( )`, `check_structure( )`).
