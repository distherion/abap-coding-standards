# HR — PA master data

> Release: the rules below are the 7.50 API of the HR framework (`cl_hrpa_*` ships with the HR component).
> PA master data framework (`cl_hrpa_*`): the BL read path, containers, buffers, plain access and the helpers around the framework. The write path — `hr-pa-write.md`.
> Related: `hr-pd.md` (PD/OM object layer), `hr-payroll.md` (payroll results, PT), `ldb.md` (LDB reads of PA/PD), `security.md` (HR authorization).

## Framework entry points

- **[P2]** Read PA master data via the class framework (`cl_hrpa_*`), not via `HR_READ_INFOTYPE` or a direct `SELECT` from `pa0001…`. A **write** does not default to the class layer either: it goes through the dispatcher `HR_CONTROL_INFTY_OPERATION`, which decides NITF vs OITF per infotype (`hr-pa-write-dispatch.md`), and the `cl_hrpa_*` write path is for the infotypes NITF is admissible for (`hr-pa-write.md`). Entry point — `cl_hrpa_masterdata_factory`: `get_read_infotype( )` → `if_hrpa_read_infotype` (`read_single`), `get_business_logic( )` → `if_hrpa_masterdata_bl`, `get_masterdata_buffer( )`, `get_read_molga( )`, `get_read_timeconstraint( )` (the read side of the time-constraint check — `if_hrpa_read_timeconstraint`: `check_admissibility( tclas pskey message_handler → is_admissible )`, `compute_timeconstraint( tclas pskey → zeitb no_admissible_gaps granularity zrmkn )`). The framework runs the authorization check and the buffer/trial logic itself; bypass only where you verified authorization yourself (`no_auth_check`, see `security.md`). Good: `cl_hrpa_masterdata_factory=>get_read_infotype( )->read_single( ... )`; bad: `HR_READ_INFOTYPE` / `SELECT ... FROM pa0001`.

- **[P2]** Infotype logic/container from the factory, not by hand: `cl_hrpa_infotype_factory=>get_infotype_logic( EXPORTING tclas infty IMPORTING infotype_logic TYPE REF TO if_hrpa_infty_bl )` — the framework's own `cl_hrpa_masterdata_bl~get_infotype_logic` is exactly this call; also `get_specific_infotype_logic( tclas infty versionid )`, `get_container_template( EXPORTING tclas infty IMPORTING template TYPE hrpad_infotype_container_ref )`, `get_container_name( tclas infty → cont_db )`. `set_context( )`/`is_context_set( )` separate `context_legacy` (`'LGCY'`) from `context_default` (`'DFLT'`) — inside a legacy context the mastered path is not available. All `RAISING cx_hrpa_violated_assertion`.

- **[P2]** `action` — the operation on the container, `if_hrpa_infotype_operation~action( EXPORTING update_mode massn massg no_auth_check message_handler operation TYPE t582itoper-operation aux_input TYPE any IMPORTING is_ok aux_output TYPE any CHANGING container TYPE hrpad_infty_container_ref )`. `operation` is a customizing code from `T582ITOPER` (not your own literal), `aux_input`/`aux_output` — the operation's payload.

- **[P2]** Buffer diagnostics and the integration contract: `cl_hrpa_buffer_trace` (`if_hrpa_masterdata_buffer`/`if_hrpa_buffer_control`/`if_hrpa_buffer_trace_events`; constructor takes the wrapped `if_hrpa_masterdata_buffer`) — `initialize_trace( )` + `evaluate_trace( IMPORTING before_images after_images TYPE hrpad_infotype_container_tab )` return the before/after images of a buffered run: wrap the buffer and inject it via `cl_hrpa_masterdata_bl=>get_instance( masterdata_buffer = ... )`, do not instrument your own code. Own buffers attach via `if_hrpa_additional_buffer~additional_update( container TYPE REF TO if_hrpa_additional_update )` + `if_hrpa_additional_update~update( )`; an external buffer/framework via `if_hrpa_framework_integration` — `start_trial`/`approve_trial`/`discard_trial` with **`CHANGING magic_cookie`** (direction differs from `if_hrpa_buffer_control`/`if_hrbas_buffer_control`, where it is `IMPORTING`/`EXPORTING` — a trap when porting), plus `initialize`, `pre_flush`, `post_flush` (the hooks `flush` calls around the buffer flush).

- **[P2]** Framework exceptions `cx_hrpa_*`/`cx_hrbas_*` — `cx_hrpa_violated_assertion` is the root (`CX_DYNAMIC_CHECK`; `cx_hrpa_invalid_parameter`, `cx_hrpa_violated_precondition`, `cx_hrpa_violated_postcondition`, `cx_hrpa_missing_lock` derive from it, so one `CATCH cx_hrpa_violated_assertion` covers the whole write layer — `read`/`insert`/`modify`/`get_infty_container`/`flush`/trial/enqueue); also `cx_hrbas_violated_assertion` (the PD root, `CX_DYNAMIC_CHECK` as well — the HRBAS tree derives from `cx_hrbas_violated_precondition` / `cx_hrbas_violated_postcond`, and from the precondition branch `cx_hrbas_invalid_parameter`, `cx_hrbas_invalid_infotype`, `cx_hrbas_invalid_db_access`, `cx_hrbas_invalid_buffer_access`, `cx_hrbas_invalid_buffer_stack`, `cx_hrbas_customization_error`; one `CATCH cx_hrbas_violated_assertion` covers the whole PD layer. Note the abbreviated name: the PD class is `..._postcond`, the PA one is `..._postcondition`), `cx_hrpa_invalid_buffer_access`, `cx_hrpa_missing_authorization` — wrap in your own `zcx_*`, do not let them leak (`errors.md`).

- **[P2]** HR feature (tables T549B/T549C/T549D, texts T549T, transaction `PE03`) — `cl_hrpa_feature=>get_value( EXPORTING feature = <name TYPE t549d-namen> struc_content = <struct> IMPORTING return_value = <val> )` (classic FM fallback — `HR_FEATURE_BACKFIELD` with `feature`/`struc_content`). A decision table for many values — `get_table( feature = ... )`. Do not `SELECT` the feature decision by hand.

- **[P3]** Constants instead of literals: TCLAS/OTYPE — `cl_hrpa_tclas=>tclas_employee` (`'A'`), `=>tclas_applicant` (`'B'`), `=>otype_employee` (`'P'`), `=>otype_applicant` (`'AP'`), conversion `tclas_to_otype( )`/`otype_to_tclas( )`, validation `assert_admissible_tclas( )`/`assert_admissible_otype( )`; dates and operations — `if_hrpa_constants`: `gc_low_date` (`'18000101'`), `gc_high_date` (`'99991231'`), `gc_infotype_operation_insert`/`_delete`/`_modify` (`'INS'`/`'DEL'`/`'MOD'`); PD/HRBAS booleans — `if_hrbas_boole_d` (`=>true`/`=>false`, the `boole_d` type the PD interfaces use: `!iv_commit TYPE boole_d DEFAULT if_hrbas_boole_d=>true`) — in PD code use it, not `abap_bool`/`'X'` (`style.md` covers the plain ABAP layer).

- **[info]** The change log (operation, before/after images, user) is written by the framework: `cl_hrpa_infotype_log` (`create private`, `get_instance`) — `log_insert( tclas new_record new_psref )`, `log_update( old_record old_psref new_record new_psref )`, `log_delete( tclas old_record old_psref )`, `flush( )`, class-event `infotype_records_flushed` (`hrpad_dboper_log_tab`), `suppress_infotype_log( iv_no_log )`. Do not write your own PA change log; suppress only for technical/mass writes.


## Read path and helpers

- **[P1]** `read` for a key with no record leaves `is_ok = abap_false` **and** adds no E/A message (the generic infotype BL exits via `CHECK` before setting `is_ok`): empty + no messages = "does not exist yet" (insert path), not a failure. Read into a fresh `cl_hrpa_message_list` and decide by `has_error( )`/`has_abend( )` — taking a bare `is_ok = false` for an error breaks every "not found → insert" case, and the framework's own postcondition (`assert_matching_error_states`: `is_ok = false` without an E/A message) raises `cx_hrpa_violated_postcondition`. <!-- rule: hrpa-bl-read-empty -->

- **[P2]** HR customizing reads (a `T*` HR table — `T001`/`T001P`/`T500P`/`T512W`/`T549A`/`T555V`/`T582*`/`T591S`/…) — the `cl_hr_t*` family (one class per table), `class-methods read( <key fields> ) RETURNING VALUE(<row>)`, buffered. `cl_hr_t001=>read( bukrs = ... )-butxt`, `cl_hr_t500p=>read( persa )-molga`, `cl_hr_t549a=>read( ... )`, `cl_hr_t591s=>read( ... )`. Use it instead of a direct `SELECT` — the class buffers and matches the table key. The rule is about the read, not about the loop: a lone `SELECT SINGLE`, and a read on the **write** path (a `PME01`/`PME04` for a feature, a check around a write), are the same defect. No class for the table — look for the standard FM first (`HR_COUNTRYGROUPING_GET`, `HR_GET_LGART_TEXT`), not a hand-written `SELECT`. A local `zcl_hr_t*` copy side-by-side with the standard family is duplication — prefer the standard class.

- **[P2]** Subtype records of one `pernr` without a structure/period walk — `HR_READ_SUBTYPE` (`pernr`/`infty`/`subty`/`begda`/`endda`, the result in `TABLES infty_tab`, typed like the infotype — `p0019`/`p0666` — and `EXCEPTIONS infty_not_found`): the standard alternative to a hand-written `SELECT ... FROM pa0019 WHERE pernr = ... AND subty = ...`. Subtype **texts** — `cl_hr_t591s=>read( )` (above). Classic FM — check `sy-subrc` and the result table right after the call (`errors.md`).

- **[P2]** Payroll retro relevance — `cl_hrpa_retrocalc` (`if_hrpa_retro_trigger` + `if_hrpa_retro_overwrite`): `is_prelp_retroactive_different( primary_infty rtype prelp1 prelp2 massn → is_different has_different_data is_admissible )`, `is_pref_retroactive_different( rtype pref1 pref2 → is_different is_admissible )`, `check_subty_retrocalc_relevant( pernr infty subty varky rtype CHANGING ct_hrpad_t588g )`; the trigger itself — `if_hrpa_retro_trigger~trigger_retro( container_tab_before container_tab_after endda_modified message_handler massn → is_ok )`. Ask the class, do not hand-`SELECT` `T588G`.

- **[P2]** Country / payroll key of a `pernr` — `cl_hrpa_country` (`read_country_by_pernr( )`, `read_country_by_intca( )`) and `cl_hrpa_molga` (`read_molga_by_pernr( )`, `read_molga_by_persa( )`) instead of a hand-made `SELECT` from `T001P`. P↔Q conversion of payroll infotypes — `if_hrpa_pq_conversion`: `pnnnn_to_qnnnn( )`/`qnnnn_to_pnnnn( )`/`pfield_to_qfield( )`/`get_qnnnn( )`.

- **[P2]** PRELP↔infotype cast — `cl_hr_pnnnn_type_cast`: `prelp_to_pnnnn( )`/`pnnnn_to_prelp( )` (single), `prelp_to_pnnnn_tab( )`/`pnnnn_to_prelp_tab( )` (table), `wplog_to_pnnnn( )`/`pnnnn_to_wplog( )`, `view_to_prelp( )`/`prelp_to_view( )`. `PRELP` is the PA buffer record (`pernr`/`infty`/`subty`/`objps`/`sprps`/`endda`/`begda`/`seqnr`); `pnnnn` — the typed infotype structure. Do not cast by hand or `MOVE-CORRESPONDING` between them. A cast PRELP **without** `GRPVL` loses the grouping value on `modify` — `hrpa-container-modify-from-buffer`.

- **[P2]** PA plain (container-less) access — `cl_hrpa_masterdata_factory=>get_plain_infotype_access( )` → `if_hrpa_plain_infotype_access` (`insert`/`modify`/`delete`/`read`/`read_single`/`read_by_pskey`/`get_initial_record`): the same operations at PNNNN level without `get_infty_container`, with the same read-mode constants as above; the mass path, for the bulk cases where the container layer is pure overhead. Bypasses the container, so use it knowingly — the container path is the default.

- **[P2]** Text and receipt clusters — through the class layer, never the cluster by hand: `cl_hrpa_text_cluster` (`class-methods read`/`read_attributes`/`update`/`delete`, all with mandatory `tclas` + `pskey` + `no_auth_check`; `read` returns `text_tab`, `read_attributes` — `itxex`/`histo`/`uname`/`aedtm`/`pgmid`) is the reader/writer of the text clusters `TX` in **PCL1** and `TY` in **PCL3**; `cl_hrpa_receipt_cluster` — of the receipt clusters `LA`/`LB`/`SA`/`SB` in **PCL4**. A hand-written `IMPORT ... FROM DATABASE pcl1(tx) ID <pskey>` is the same defect as a hand-read payroll cluster (`hr-payroll.md`, `payroll-no-hand-cluster`): the components are mapped by layout, not by name, so a structure change lands the lines in the wrong components with no error, and the version handling of the class is skipped. `no_auth_check` is the authorization of the underlying record — pass it deliberately (`security.md`).

- **[P1]** A **specific record** (e.g. by `begda` from a list) — pass the key to the framework read, do not filter a hand-written `SELECT ... FROM pa0001 WHERE pernr = ... AND begda = ... AND endda = ...`: the framework applies auth + period logic and returns the exact record, and `read_single` without a date gives the current/latest. `if_hrpa_masterdata_bl~read` picks the record by a named read mode — `mode TYPE hrpad_read_mode DEFAULT all_intersecting_records`; the enumeration is `last_intersecting_record` = 0, `first_intersecting_record` = 1, `last_record_containing_endda` = 2, `first_record_containing_begda` = 3, `exact_matching_record` = 4, `all_intersecting_records` = 5, `all_included_records` = 6 (the same names and values on `if_hrpa_infty_bl`/`if_hrpa_plain_infotype_access` and on the PD `if_hrbas_dispatch_bl`) — use the constant, not a literal number. <!-- rule: hr-read-mode -->

- **[P2]** `PERNR`-level loops over a whole workforce — do not `SELECT` one `pa0001` row per `pernr`; retrieve the whole selection set in one read (the framework / a single bulk read) and group by `pernr`, then split the processing (see `open-sql.md`; `parallel.md` for bgRFC splits).


## Bypass paths and debugging

- **[P2]** Bypass paths — every one of them skips framework checks; use knowingly and never in the ordinary write path: `if_hrpa_masterdata_db` (`cl_hrpa_masterdata_db`: `update( oper_tab no_commit )`, `read( tclas pernr infty … → container_tab )`, class-event `data_flush_completed`) — the raw DB layer under the buffer; `cl_hrpa_infty_no_checks` (a `cl_hrpa_infty_nnnn` descendant overriding `check_business_pskey_constr`/`check_foreign_keys`/`read_metadata_by_structdescr` to `is_ok = true`) — the "no checks" infotype logic. The PA buffer is invisible to the raw DB layer: a direct legacy `HR_INFOTYPE_OPERATION` inside a framework session desynchronises the P-buffer, and repairing it takes `HR_PSBUFFER_INITIALIZE` (plus the P-buffer refill program) — which is why the *legacy call* must not be mixed with a framework session. The dispatcher write is not that bypass: it is the ordinary write entry (`hr-pa-write-dispatch.md`), it takes its own class branch when the infotype is admissible for NITF, and where it sends the infotype to the module pool the class write path is not an alternative at all.

- **[behavior]** Reading a runtime dump (`ST22`) against the local abapGit export: a method frame prints `PROGRAM=...=CM00x:LINE`, and `LINE` is the source line **within the method** (`METHOD` statement = line 1) — so the frame chain maps onto the local file one-to-one and shows which statement raised and whether the active revision is the one you shipped. The include *letters* (`CM00S`) are assigned by the object's activation history and do not follow the current method order; the line numbers do.
