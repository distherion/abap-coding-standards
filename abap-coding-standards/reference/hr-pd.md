# HR — PD / OM object layer

> Release (7.50): the PD object layer (`cl_hrbas_*`, EA-HR 7.40+) and the `RH_*` FMs exist on the target release.
> PD/OM object layer: `cl_hrbas_*` object/dispatch/plain access, `RH_*` reads, OM locks. The PD write path — `hr-pd-write.md`; the PD message handler, the OM buffer and the PD authorization helpers — `hr-pd-msg-buffer.md`.
> Related: `hr-pa.md` (PA master data), `ldb.md` (LDB reads of PA/PD), `security.md` (HR authorization).

## Read path and object layer

- **[P1]** OM/PD read — a structure: `RH_STRUC_GET` (`act_otype`/`act_objid`/`act_wegid`/`act_plvar`/`act_begda`/`act_endda` → `TABLES result_objec`). One object's infotypes: prefer the class layer — `cl_hrbas_read_infotype=>get_instance( IMPORTING infty_buffer OPTIONAL infty_plain_buffer OPTIONAL RETURNING VALUE(infotype_reader) )` (`create private`, only via `get_instance`, `RAISING cx_hrbas_violated_assertion`), then `read( plvar otype objid infty subty istat begda endda condition fill_buffer objects no_auth_check no_ext_infties IMPORTING container_tab missing_auth data_exists )` — `plvar`/`otype`/`objid` optional (or pass `objects`), `begda`/`endda` default `if_hrbas_constants=>low_date`/`high_date`, `fill_buffer` default `abap_true`; also `read_plain`, `read_1001`, `read_plain_1001`, `read_translations`. Distinguish "no data" from an error by `data_exists`/`missing_auth`, not by an empty `container_tab`. The legacy `RH_READ_INFTY` (`infty`/`subty`/`begda`/`endda` → `TABLES innnn`/`objects`) — only where the class layer does not fit. <!-- rule: pd-read-infotype -->

- **[P1]** Object-layer relations — `if_hrbas_pd_object~get_relations`: an empty `relations` is "no relation" **only** with `is_ok = abap_true`. `is_ok = abap_false` is a failure whose text sits in the passed `cl_hrbas_message_list`; **does not exist:** `missing_auth` on the object layer — an authorization denial arrives exactly this way, unlike `cl_hrbas_read_infotype`, which reports it in its own exporting parameter (`pd-read-infotype`). Clearing the table on `is_ok = abap_false`, or on a `CATCH cx_hrbas_violated_assertion`, turns a denial into "no relation" — and the caller's next step on that verdict is `create_relation` (`errors.md`, `catch-into-default`). Read `is_ok` and the message list, and hand the failure up as a `RETURNING` error object or your own `zcx_*`. <!-- rule: pd-relations-empty-on-error -->

- **[P2]** A structure for **many** roots — one call `RH_STRUC_GET_MULTIPLE_ROOTS` instead of `RH_STRUC_GET` per root in a loop: `TABLES root_objects` is a table of `HRROOTOB` (`otype` + `objid`, and the `objid` is a `REALO` — the extended object ID, i.e. the external key for an external otype), the FM evaluates the whole table in **one** structure build (`STRUCTURE_BUILD_MULTIPLE_ROOTS`) and returns the union in `result_objec` (`OBJEC`) / `result_struc` (`STRUC` — `pup`/`level`/`seqnr`, the parent link). Set explicitly what the defaults hide: `act_begda`/`act_endda` default to `sy-datum` (the call site means the period of the report, not today) and `act_tdepth` default `0` is unlimited depth; leave `authority_check = 'X'` alone — switching it off "to make it work" is the authorization bypass of `security.md`. The rows carry **no** root attribution → sort and `DELETE ADJACENT DUPLICATES`; `keep_order` restores the root order for `act_tdepth` 1/2 only. The exceptions are classic (`no_plvar_found`/`no_entry_found`/`root_not_found`/`path_not_found`) — `EXCEPTIONS OTHERS = 0` turns "nothing found" into an empty table that reads as success (`errors.md`, "A legacy FM call site").

- **[info]** The plan version (`plvar`) is not a literal: `RH_GET_PLVAR` / `RH_GET_ACTIVE_WF_PLVAR` (the plan version active for the current OM/workflow context) return it — pass their result into the `RH_*` calls and the object layer. Same for `istat`: `'1'` (active) is the standard default of the read APIs (`cl_hrbas_object_operations`), not a value to hard-code from a test system.

- **[P2]** Object attributes, descriptions, relations and input help outside the object layer — standard and still current: `RH_OM_ATTRIBUTES_READ` (attribute values of an object), `RH_OBJECT_DESCRIPTION_READ` (short/long text), `RH_READ_OBJECT` (one object by key), `RH_READ_INFTY_1001` / `RH_READ_INFTY_1000` (relations / objects without a structure walk, i.e. no `RH_STRUC_GET`), `RH_OBJID_REQUEST` (object F4). For the F4 prefer the class — `cl_hrbas_generic_f4_help`; a hand-written `SELECT ... FROM hrp1000` for a description or an object list is the classic defect here.

- **[P2]** PD plain (container-less) access — `cl_hrbas_plain_infotype_access` (`create public`, interfaces `if_hrbas_buffer_control` + `if_hrbas_plain_infotype_access`, constructor takes the `dispatch_bl` reference): `insert`/`modify`/`delete` with `CHANGING pnnnn TYPE ANY` (+ optional `hrtnnnn_tab`, `old_hripkey`) and `read`/`read_single`/`read_by_hripkey`/`get_initial_record`; `update_mode`/`no_auth_check` here are `OPTIONAL`, the same `is_ok`/`message_handler`/`cx_hrbas_violated_assertion` scheme. The mass/bulk path at PNNNN level — the pairing for `cl_hr_pnnnn_type_cast` (in `hr-pa.md`); it bypasses the container layer, so use it knowingly.

- **[P2]** PD object layer — instances: `create_object( otype short … → pd_object is_ok )`, `get_object_instance( otype objid … )`, `get_universal_object( otype realo … )`; `pd_object_classname` defaults to `cl_hrbas_pd_object` (own classes allowed) and the instances are cached in `cl_hrbas_pd_object_repository=>get_instance( )` (`get_object_instance`/`add_object_instance`/`remove_all_object_instances`). Lifecycle: `delete_object( )`, `change_object_validity( new_date mode … )` with `hrbas_validity_change_mode` (0 delimit / 1 extend / 2 new endda / 3 new begda; `adapt_infotypes` DEFAULT `'X'`); per-object buffer `initialize_buffer( )`/`initialize_buffer_for_object( )`/`update_buffer_for_object( )`. Locks: `set_exclusive_lock`/`set_optimistic_lock`/`set_shared_lock( … message_handler → is_ok )` + `remove_*_lock( )`, the optimistic one is meant to be promoted — `promote_lock_to_exclusive( )` / `is_optimistic_lock_promotable( )`; `enq_collect` default here is `' '` (the PA enqueue uses `'X'`). The admin only delegates — the actual lock layer is `cl_hrbas_lock_manager`, all methods `class-methods` (`set_exclusive_lock( EXPORTING plvar otype objid enq_scope = '2' enq_wait = ' ' enq_collect = ' ' message_handler IMPORTING locking_user is_ok )`, `RAISING cx_hrbas_violated_assertion`); the `remove_exclusive_lock`/`remove_optimistic_lock`/`remove_shared_lock( plvar otype objid )` take **no** `message_handler`, return **no** status and declare no `RAISING` — an unlock has no result to check. The key is the `objid`, or the `realo` for an external object with an 8-char key (the admin asserts this) — an empty key is not lockable. The admin methods return `is_ok` and declare no `RAISING` — `cx_hrbas_violated_assertion` comes from the lock manager and the instance methods.

- **[P1]** PD instances — an initial `objid` is not validated and ends in a dump: `get_object_instance` asserts `objid IS NOT INITIAL`, and the `cl_hrbas_pd_object` constructor checks existence and asserts the result (`ASSERT is_ok = true.`, `ASSERT sy-subrc = 0.`) — an empty key gives an `ASSERT` dump (`ASSERTION_FAILED`), not `is_ok = false` and not a catchable exception (in the same admin class `create_object` checks only `otype`/`short`/`message_handler` and inserts `p1000-objid = objid` as is). The sanctioned pre-check — `cl_hrbas_object_operations=>get_instance( )`: `exist_object( EXPORTING plvar otype objid IMPORTING is_ok histo existance_tab )`, `read_object( plvar otype objid istat = '1' langu = sy-langu begda endda no_auth_check fill_buffer → is_ok obeg oend histo short stext tlangu )`, also `delete_object`, `change_object_timeperiod`, `historicize_object` — existence without an object instance and without a dump. Check `otype`/`objid` (external objects — `realo`) before creating an instance; the same scheme sits in `cl_hrbas_pd_object=>ensure_call_consistence` (an initial `plvar`/`otype`/`objid` sets `is_consistent = false`, and the infotype methods then hit `ASSERT is_consistent = true`). <!-- rule: pd-object-empty-objid -->

- **[P1]** PD object layer and **external** object types (the personnel number `'P'`, the cost center): the instance methods end in an `ASSERTION_FAILED` dump — not in `is_ok = false`, and not in a catchable exception. The gate is `check_and_get_plain_obj_param( assure_internal_object = 'X' )`, whose last step is an active `ASSERT cl_hrbas_infotype_services=>is_external_otype( otype ) IS INITIAL` (`cl_hrbas_pd_object_admin`); `get_object_instance` even carries the comment `* It must no be used for external objects.` <!-- rule: pd-external-otype-gate -->
  - **Gated** (assert): `get_object_instance` (via `get_object_internal`), `delete_object`, `change_object_validity`, `initialize_buffer_for_object`, `update_buffer_for_object`, `set_optimistic_lock`, `remove_optimistic_lock`, `promote_lock_to_exclusive`, `is_optimistic_lock_promotable`, `set_shared_lock`, `remove_shared_lock`.
  - **Not gated:** `set_exclusive_lock` and `remove_exclusive_lock` — their `ASSURE_INTERNAL_OBJECT` is commented out (`* ASSURE_INTERNAL_OBJECT = ''`), which is why locking works for externals where the instance methods do not.
  - **"External" is customizing, not a property of the otype:** a row in **T77EO**. `cl_hrbas_infotype_services=>is_external_otype` calls `RH_GET_EXTERNAL_OBJECT_INFO`, and the object layer branches on `cl_hr_t77eo=>read( otype )` itself — a row means external (existence and texts via `RH_READ_OBJECT`), no row means internal (IT1000 from the buffer: `cl_hrbas_object_operations=>exist_object` / `=>read_object`). Call `cl_hrbas_infotype_services=>is_external_otype( otype = … )`; do not assume it from the otype.
  - **Route for externals:** `get_universal_object( plvar otype realo message_handler → universal_object is_ok )` — no gate, the key goes in `realo` (not `objid`), existence via `exist_object`, so a missing object is `is_ok = false` plus the `5A 105` message instead of a dump. Locking such an object — `set_exclusive_lock( universal_object = … )` / `remove_exclusive_lock( universal_object = … )`, the key then comes from `realo`, with `ASSERT objid = l_realo. "Only internal or external objects with an OBJID/REALO of 8 chars can be locked/unlocked` — an external key longer than 8 chars is not lockable through this API.

- **[info]** `if_hrbas_pd_object` — the object instance (`a_objid`; via `if_hrbas_universal_object` also `a_plvar`/`a_otype`/`a_realo`/`a_is_external_object`, read-only). Infotypes: `read_infty( infty subty begda endda istat … → pnnnn_tab hrtnnnn_tab is_ok )`, `insert_infty`, `modify_infty( old_key … )`, `delete_infty( key … )`, `delimit_infty( old_key delimit_date … )` — the record goes in **`CHANGING pnnnn TYPE ANY`** (+ optional `hrtnnnn_tab`), i.e. the infotype logic edits the caller's structure in place. Relations: `get_relations` / `get_related_objects` / `create_relation` / `modify_relation( old_key … )` / `delete_relation( key )` / `delimit_relation( old_key delimit_date )`. Descriptions: `get_description` / `get_descriptions` / `insert_description` / `modify_description` / `get_general_description` / `insert_general_description` / `modify_general_description` / `delete_general_description`. Existence: `get_existence( → lowest_begda highest_endda all_existencies )` — the only method with the classic `EXCEPTIONS OBJECT_DOES_NOT_EXIST`. Common parameters `message_handler`/`no_auth_check`/`update_mode`, result `is_ok`, raises `cx_hrbas_violated_assertion`. `if_hrbas_universal_object` carries the same read side (relations, descriptions, existence) for an object without a PD-object instance — external objects (`a_is_external_object`), for which `change_object_validity` must not be called.

- **[P1]** A relation with an external partner: `create_relation` takes **exactly one** of `related_pd_object` / `related_universal_object` — in `cl_hrbas_pd_object` the pair is asserted (`ASSERT related_universal_object IS INITIAL OR related_pd_object IS INITIAL.` plus the inverse) and the key is filled from whichever came in (`sobid = related_pd_object->a_objid` / `sclas = …a_otype` against `sobid = related_universal_object->a_realo` / `sclas = a_otype`). For an 8-char key (the pernr) both branches write the **same** P1001 row, so the pattern is *internal host object + external partner as a universal reference*: create the relation on the C/O/S object with `related_universal_object` = the person, instead of instantiating the person as a PD object (which dumps — `pd-external-otype-gate`). The host is then only a driver: `modify_relation` delegates to the plain access (`a_plain_access->modify( old_hripkey = old_key … )`, `cl_hrbas_pd_object`), which addresses the record by `old_hripkey`/`pnnnn` alone (`cl_hrbas_plain_infotype_access`) — the instance's own key does not scope the write, and a record that is neither in the buffer nor in the DB makes it fail with `HRBAS_ITF 101` ("the record to be changed is not there before the change"). <!-- rule: pd-relation-external-partner -->
