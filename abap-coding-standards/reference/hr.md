# HR (PA / OM / payroll)

> HR master data, organizational management and payroll access. Authorization context — `security.md` (P_ORGIN, reader bypass), locks and trial pattern — `errors.md`, logical database — `ldb.md`.

- **[P2]** Read/change PA master data via the class framework (`cl_hrpa_*`), not via legacy FMs (`HR_READ_INFOTYPE`, `HR_INFOTYPE_OPERATION`) or direct `SELECT` from `pa0001…`. Entry point — `cl_hrpa_masterdata_factory`: `get_read_infotype( )` → `if_hrpa_read_infotype` (`read_single`), `get_business_logic( )` → `if_hrpa_masterdata_bl`, `get_masterdata_buffer( )`, `get_read_molga( )`, `get_read_timeconstraint( )`. The framework runs the authorization check and the buffer/trial logic itself; bypass only where you verified authorization yourself (`no_auth_check`, see `security.md`). Good: `cl_hrpa_masterdata_factory=>get_read_infotype( )->read_single( ... )`; bad: `HR_READ_INFOTYPE` / `SELECT ... FROM pa0001`.
- **[P2]** HR feature (table T549A/B, transaction `PE03`) — `cl_hrpa_feature=>get_value( EXPORTING feature = <name TYPE t549d-namen> struc_content = <struct> IMPORTING return_value = <val> )` (classic FM fallback — `HR_FEATURE_BACKFIELD` with `feature`/`struc_content`). A decision table for many values — `get_table( feature = ... )`. Do not `SELECT` the feature decision by hand.
- **[P3]** TCLAS/OTYPE — constants, not literals: `cl_hrpa_tclas=>tclas_employee` (`'A'`), `=>tclas_applicant` (`'B'`), `=>otype_employee` (`'P'`), `=>otype_applicant` (`'AP'`); conversion `tclas_to_otype( )`/`otype_to_tclas( )`; validation `assert_admissible_tclas( )`/`assert_admissible_otype( )`.
- **[P2]** HR messages — `cl_hrpa_message_list` (instantiate with `NEW`, no factory — unlike `cf_reca_message_list=>create`), producer interface `if_hrpa_message_handler`. Same accumulate/query pattern as `cl_reca_message_list` — `logging.md` (`add_messages`, `has_error`/`has_abend`, `get_message_list`).
- **[P2]** HR customizing table reads — the `cl_hr_t*` family (one class per table, ~68 classes), `class-methods read( <key fields> ) RETURNING VALUE(<row>)`, buffered. `cl_hr_t001=>read( bukrs = ... )-butxt`, `cl_hr_t549a=>read( ... )`, `cl_hr_t591s=>read( ... )`, `cl_hr_t500p=>read( ... )`. Use it instead of a direct `SELECT` from `T001`/`T549A`/`T591S`/… — the class buffers and matches the table key.
- **[P2]** OM/PD read — `RH_STRUC_GET` (`act_otype`/`act_objid`/`act_wegid`/`act_plvar`/`act_begda`/`act_endda` → `TABLES result_objec`) for a structure; `RH_READ_INFTY` (`infty`/`subty`/`begda`/`endda` → `TABLES innnn`/`objects`) for one object's infotype. Write — only via the PD object layer (`cl_hrbas_*`), never `RH_INSERT_INFTY`/`RH_MODIFY_INFTY`/direct `HRP1000`/`HRP1001`: entry `cl_hrbas_pd_object_admin=>get_instance( )`; trial `start_trial`/`discard_trial`/`approve_trial`+`flush` (see `errors.md`); locks `set_exclusive_lock`/`set_optimistic_lock`/`set_shared_lock` + `remove_*`; lifecycle `create_object`/`delete_object`/`change_object_validity`. Object instance (`if_hrbas_pd_object`): infotypes `read_infty`/`insert_infty`/`modify_infty`/`delete_infty`/`delimit_infty`; relations `get_relations`/`get_related_objects`/`create_relation`/`modify_relation`/`delete_relation`/`delimit_relation`; description `get_description`/`get_descriptions`/`get_general_description`. Common params `message_handler`/`no_auth_check`/`update_mode`, result `is_ok`; raises `cx_hrbas_violated_assertion`.
- **[P2]** Payroll result (PCL2) — `PYXX_READ_PAYROLL_RESULT` (`clusterid`/`employeenumber`/`sequencenumber` → `payroll_result`); fill `payroll_result-evp` with `MOVE-CORRESPONDING` from the `RGDIR` row (`<ls_rgdir>-seqnr`). Do not read `PCL2` directly.
- **[P2]** PRELP↔infotype cast — `cl_hr_pnnnn_type_cast`: `prelp_to_pnnnn( )`/`pnnnn_to_prelp( )` (single), `prelp_to_pnnnn_tab( )`/`pnnnn_to_prelp_tab( )` (table), `wplog_to_pnnnn( )`/`pnnnn_to_wplog( )`, `view_to_prelp( )`/`prelp_to_view( )`. `PRELP` is the PA buffer record (`pernr`/`infty`/`subty`/`objps`/`sprps`/`endda`/`begda`/`seqnr`); `pnnnn` — the typed infotype structure. Do not cast by hand or `MOVE-CORRESPONDING` between them.
- **[P3]** Text/receipt clusters — `cl_hrpa_text_cluster` (PCL1) / `cl_hrpa_receipt_cluster` (PCL4).
- **[P3]** RU date tools — `cl_hrpadru_date_tools`: `last_day_in_month( )`, `next_period( )`. (General date arithmetic — `cl_reca_date` in `data.md`.)
- **[P3]** Framework exceptions `cx_hrpa_*`/`cx_hrbas_*` (`cx_hrpa_violated_assertion`, `cx_hrbas_violated_assertion`, `cx_hrpa_invalid_buffer_access`, `cx_hrpa_missing_authorization`, `cx_hrpa_missing_lock`, …) — wrap in your own `zcx_*`, do not let them leak (see `errors.md`).
