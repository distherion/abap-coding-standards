# Logical database (LDB-PNP / PNPCE)

- **[P2]** The PNPCE logical database is the standard HR read mechanism — prefer `GET peras` over a hand-rolled `SELECT` loop over `pa0001`/`pa0007`. The LDB fills the declared infotype tables (`pnnnn[]`) for the whole selection period and applies the HR authorization filter; a manual `SELECT` gets neither (auth — see `security.md`).
- **[P2]** New reports — PNPCE (`GET peras`); classic PNP (`GET pernr`) is obsolete, do not use for new code. Never both in one report. `GET pernr` is not available in PNPCE. In both, the declared `pnnnn[]` tables are already filled when the event fires.
- **[P3]** Declare the infotypes a report reads via `INFOTYPES: 0001, 0002, ...` — do not re-`SELECT` an infotype the LDB already provided. PNPCE adds `INFOTYPES ... AS PERSON TABLE` to fill the infotype for all personnel numbers of a person/group (not just the current `peras`) — mind the authorization scope.
- **[P3]** Skip the current employee/record inside the LDB event with `REJECT` (e.g. `IF p0000[] IS INITIAL. REJECT. ENDIF.`), not a wrapper `IF` around the whole block.
- **[P2]** Date-interval slicing over an infotype — `RP_PROVIDE_FROM_LAST p0001 space pn-begda pn-endda` / `RP_PROVIDE_FROM_FRST`, not a manual `LOOP` + `begda`/`endda` comparison. The macro puts the latest/oldest valid record into the table header and sets `PNP-SW-FOUND` (`1` = found, `0` = none) — `REJECT`/handle when `0`. Meaningful only for an infotype with time constraint 1/2 and a table sorted ascending.
- **[info]** PNPCE (SAP recommends it for new developments) — `GET peras` replaces `GET pernr`; `TABLES: pernr` declares the work area but only `pernr-pernr` is filled, the rest stay initial. CE mode activates only when the report uses `GET person`/`GET group`/`AS PERSON TABLE`; without them it runs PNP-compatible (`GET peras` per personnel number).
- **[info]** CE node hierarchy `person → group → peras`: `GET person` fires once per natural person (`person-objid`, `person-pernr_num`, `person-all_pernrs`, `selected`/`process` flags); `GET group` per grouping reason (`group-grouping_reason`, `group-grouping_value`, `group-all_pernr`); `GET peras` per assignment. Declare the nodes with `NODES: person, group, peras.`
- **[P3]** Re-drive an LDB report from another program — `SUBMIT <report> VIA SELECTION-SCREEN` (reuses its selection screen + LDB), not re-implementing the selection.
