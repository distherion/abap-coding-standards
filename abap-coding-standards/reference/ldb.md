# Logical database (LDB-PNP / PNPCE / PCH)

- **[P2]** The PNPCE logical database is the standard HR read mechanism — prefer `GET peras` over a hand-rolled `SELECT` loop over `pa0001`/`pa0007`. The LDB fills the declared infotype tables (`pnnnn[]`) for the whole selection period and applies the HR authorization filter; a manual `SELECT` gets neither (auth — see `security.md`).
- **[P2]** New reports — PNPCE (`GET peras`); classic PNP (`GET pernr`) is obsolete, do not use for new code. Never both in one report. `GET pernr` is not available in PNPCE. In both, the declared `pnnnn[]` tables are already filled when the event fires.
- **[P3]** Declare the infotypes a report reads via `INFOTYPES: 0001, 0002, ...` — do not re-`SELECT` an infotype the LDB already provided. PNPCE adds `INFOTYPES ... AS PERSON TABLE` to fill the infotype for all personnel numbers of a person/group (not just the current `peras`) — mind the authorization scope.
- **[P3]** Skip the current employee/record inside the LDB event with `REJECT` (e.g. `IF p0000[] IS INITIAL. REJECT. ENDIF.`), not a wrapper `IF` around the whole block.
- **[P2]** Date-interval slicing over an infotype — `RP_PROVIDE_FROM_LAST p0001 space pn-begda pn-endda` / `RP_PROVIDE_FROM_FRST`, not a manual `LOOP` + `begda`/`endda` comparison. The macro puts the latest/oldest valid record into the table header and sets `PNP-SW-FOUND` (`1` = found, `0` = none) — `REJECT`/handle when `0`. Meaningful only for an infotype with time constraint 1/2 and a table sorted ascending.
- **[info]** PNPCE (SAP recommends it for new developments) — `GET peras` replaces `GET pernr`; `TABLES: pernr` declares the work area but only `pernr-pernr` is filled, the rest stay initial. CE mode activates only when the report uses `GET person`/`GET group`/`AS PERSON TABLE`; without them it runs PNP-compatible (`GET peras` per personnel number).
- **[info]** CE node hierarchy `person → group → peras`: `GET person` fires once per natural person (`person-objid`, `person-pernr_num`, `person-all_pernrs`, `selected`/`process` flags); `GET group` per grouping reason (`group-grouping_reason`, `group-grouping_value`, `group-all_pernrs`); `GET peras` per assignment. Declare the nodes with `NODES: person, group, peras.`
- **[P3]** Re-drive an LDB report from another program — `SUBMIT <report> VIA SELECTION-SCREEN` (reuses its selection screen + LDB), not re-implementing the selection.
- **[info]** The selection period of an LDB (HR) — from `pn-begda`/`pn-endda`, which the LDB fills and bounds the interval for which the `get pernr`/`get peras` event fires and the `pnnnn[]` tables are filled. The report reads them inside the event — they are valid there, do not recompute. When presenting the selection to the user, provide `pn-begda`/`pn-endda` on the selection screen via the standard LDB selections so the covered interval is explicit, and default them to the current date/period in `INITIALIZATION` — an unconstrained or defaulted-to-`sy-datum` range makes the event fire for an unintended window (a single day or the full history).
- **[P3]** Do not `SELECT` from `T549A`/`T001`/other HR customizing inside the `GET` event per row — the LDB events fire per personnel number/assignment; a `SELECT` there is a `SELECT` in a loop (see `open-sql.md`). Read once before the loop (per `molga`/country grouping) or use the buffered `cl_hr_t*` classes (`hr.md`).
- **[info]** `RP_PROVIDE_FROM_LAST` fills the infotype **header** (`p0001-begda/endda`, `p0001-pernr`, ...) with the record that is current/latest in the period; the header field `pn-begda`/`pn-endda` of the infotype work area is set from the selection. After the macro, compare `p0001-begda`/`p0001-endda` against the requested period before use — a "last" record may start before `pn-begda` (time constraint 1 spills over the boundary) and the caller must decide overlap.
- **[P3]** `RP_PROVIDE_FROM_LAST`/`RP_PROVIDE_FROM_FRST` need the infotype table sorted ascending by `begda` and a time constraint where "last/first" is unambiguous (per the constraint note above); for a time-constraint-3 infotype (multiple parallel records) filter by date in a `LOOP` instead of trusting "last".

## Logical database PCH (Personnel Planning / OM)

- **[P2]** For Organizational Management (PD/OM) structure reports prefer the PCH logical database — `GET objec` — over a hand-rolled `SELECT` loop over `hrp1000`/`hrp1001`. The LDB walks the evaluation path / object selection, fills the declared `pnnnn[]` tables for each object, and applies the PD authorization filter; a manual `SELECT` gets none of it. PCH reads OM objects (`O`/`S`/`C`/…); PNP/PNPCE reads employees — do not mix in one report.
- **[info]** Report attribute "Logical database" must be `PCH`. `TABLES: objec` (or `NODES: objec`) enables the `GET objec` event; `TABLES: gdstr` / `NODES: gdstr` switches selection from key-based to structural/evaluation-path mode (fills the hierarchy root, `gdstr`). Declare the infotypes to read with `INFOTYPES: 1000, 1001, 1002, ...` — the LDB fills `p1000[]`, `p1001[]`, … for the current object when `GET objec` fires (do not re-`SELECT` them).
- **[info]** `GET objec` fires once per selected object; the current object sits in the `objec` work area (`objec-plvar`, `objec-otype`, `objec-objid`, `objec-stext`, `objec-realo` = 8-char object ID). Skip an object with `REJECT`.
- **[info]** PCH selection screen: `pchplvar` (plan version), `pchotype` (object type), `pchobjid` (object ID), `pchwegid` (evaluation path), `pchdepth` (depth), `pchbegda`/`pchendda` (key date), `pchobeg`/`pchoend` (object selection period), `pchztr_z`, `pchseark`. Re-drive from another report — `SUBMIT <report> WITH pchplvar = ... WITH pchotype = ... WITH pchobjid IN s_objid WITH pchobeg = ... WITH pchoend = ...`.
- **[P3]** Table-part OM infotypes (`hrp1002`, `hrp1222`, … — `HRP*` + `HRT*` joined by `tabnr`) — read the tabular part via `RH-GET-TBDAT '1002' <pnnnn>-tabnr lt_pt1002` (or `RH_READ_INFTY_TABDATA`), not a hand `SELECT` from `hrt1002`/`hrtnnnn`.
- **[P3]** Pre-filter infotype records inside the LDB read — `RH-SET-INDEX-INFTY '1003'.` / `RH-CONDITION-LINE <field> EQ 'X' SPACE.` / `RH-SET-INDEX-INFTY-CONDITION.`; restrict the selection screen with `RH-SEL-ONE-OBJID` / `RH-SEL-KEYDATE`.
