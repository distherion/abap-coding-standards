# OData v4 (SEGW V4, `/IWBEP/IF_V4_*`)

> **[info]** In 7.50 v4 is available via SAP Gateway (SEGW, service type V4) **only with a recent Gateway component (from ~7.50 SP04+)** — verify the SEGW/service-type support on the target system; a plain 7.40/7.50 base may not have it. The API is `edm`-style, namespace `/IWBEP/IF_V4_*`, differs from v2 (`/IWBEP/IF_MGW_*`). Do not mix: the v2 specifics ($batch CHANGESET, ETag `GET_IS_CONDITIONAL_IMPLEMENTED`, `/IWBEP/CX_MGW_BUSI_EXCEPTION`) — not for v4; v2 rules — `reference/odata.md`.

- **[P2]** Write v4 service classes yourself by inheriting from the standard ones, do not edit the generated ones: model (`$metadata`/EDMX) — a descendant of `/IWBEP/CL_V4_ABS_MODEL_PROV` (exactly `_PROV`), method `/IWBEP/IF_V4_MP_BASIC~DEFINE`; data (CRUD) — a descendant of `/IWBEP/CL_V4_ABS_DATA_PROVIDER` (there **is** an umbrella `/IWBEP/IF_V4_DATA_PROVIDER`, but it is only a composite of the five granular interfaces — `/IWBEP/IF_V4_DP_ADVANCED` + `DP_BASIC` + `DP_BATCH` + `DP_INTERMEDIATE` + `DP_PROCESS_STEPS` — do not implement "one method" on it; you implement the granular interfaces, and `/IWBEP/CL_V4_ABS_DATA_PROVIDER` already implements the umbrella).
- **[P2]** CRUD in the data provider — the **read** side is uniformly `/IWBEP/IF_V4_DP_BASIC`: `read_entity_list` (collection), `read_entity` (by key), and `read_ref_target_key_data(_list)` (reference/expansion reads are also on `DP_BASIC`, not `DP_ADVANCED`). The **whole CRUD set** exists on **both** `DP_BASIC` and `DP_ADVANCED` (`create_entity`/`update_entity`/`delete_entity`/`execute_action`/`execute_function`/`read_entity`/`read_entity_list`): the `DP_BASIC` variants throw `/iwbep/cx_v4_not_implemented` by default (you must implement them), while the `DP_ADVANCED` variants have a default implementation in `/iwbep/cl_v4_abs_data_provider` that delegates to `DP_BASIC`/`DP_INTERMEDIATE` — redefine them (`/iwbep/if_v4_dp_advanced~create_entity` etc.) only for full control of a complex case and call `super` for the cases you do not handle. Follow the pattern your generated/superclass class uses, verify the method set in SE24. Function imports/actions: `/iwbep/if_v4_dp_basic~execute_function` and `/iwbep/if_v4_dp_basic~execute_action` **are real, redefinable methods** (implemented in working services; dispatch by the function/action name and call `super` for the rest) — do not claim they do not exist. `DP_ADVANCED`/`DP_INTERMEDIATE`/`DP_PROCESS_STEPS` — additionally for advanced/deep/tree scenarios (e.g. `patch_entity`, `read_entity_tree(_list)`, `initialize`/`commit`/`rollback`) — their exact method sets vary by release, verify in SE24 on the target system.
- **[P2]** Dispatch: `io_request->get_entity_set( )`/`get_entity_type( )` → `CASE` by name; `WHEN OTHERS` → call super (`/iwbep/if_v4_dp_basic~create_entity( io_request = ... io_response = ... )`), do not raise "not implemented" yourself.
- **[P2]** To-do flags: `io_request->get_todos( IMPORTING es_todo_list = ls_todo_list )`. The todo structure differs per interface: for the **basic read** (`/IWBEP/IF_V4_REQU_BASIC_READ`) the process flags are `ls_todo_list-process-key_data`, `process-select`, `process-if_none_match_etag`, and the return flag is `ls_todo_list-return-busi_data` (there is **no** `process-busi_data` in the read list — `process-busi_data`/`process-target_key_data`/`process-navigation`/`process-deep_busi_data` live only in the *advanced* create/update todo structure). Process the entity only if `ls_todo_list-process-key_data = abap_true`; return `io_response->set_busi_data( ls_data )` only if `ls_todo_list-return-busi_data = abap_true`. Call `io_response->set_is_done( ls_todo_list-process )` — it takes the **process** sub-structure (`TY_S_TODO_PROCESS_LIST`), not the whole todo list — **only for the options actually processed**; an unconditional flag marks everything as done and the framework does not raise "not implemented".
- **[P2]** Errors: `CATCH /iwbep/cx_gateway`; messages — via the response's `get_message_container( )`, which returns the interface `/IWBEP/IF_V4_MESSAGE_CONTAINER` (the concrete class is `/iwbep/cl_v4_message_container`): `get_messages( IMPORTING et_message )`, `add_exception( io_exception, iv_msg_type, iv_is_for_user )`, `has_leading_message_for_user( )`. Propagate further: `RAISE EXCEPTION TYPE /iwbep/cx_gateway EXPORTING http_status_code = ... message_container = ... is_for_user = abap_true.` (or `textid = VALUE #( msgid = ... msgno = ... attr1 = ... attr2 = ... )` with the SE91 message) — not `/IWBEP/CX_MGW_BUSI_EXCEPTION` — that is v2.
- **[P2]** Do not invent v4 (`edm`) annotations in the model provider — verify the name/type against the `/IWBEP/` doc or a generated SEGW service (see "Finding sources" in SKILL.md).
- **[info]** Model: in `define`, add a private method per entity type/set (`define_*( io_model )` with `io_model TYPE REF TO /iwbep/if_v4_med_model`), not one big sheet. The `DEFINE` signature has a second parameter `io_model_info TYPE REF TO /iwbep/if_v4_model_info` (usually unused but part of the interface). A common helper to "create an entity from a structure" (see below).
- **[info]** Entity type from an ABAP structure: `io_model->create_entity_type_by_struct( iv_entity_type_name, is_structure, iv_gen_prim_props = abap_true ... )` (auto-generates primitive properties from the structure fields); `->create_entity_set( iv_entity_set_name )`; `->set_edm_name( ... )` for both type and set. Key — `get_primitive_property( '<field>' )->set_is_key( )`.
- **[info]** Fine-tuning a field type: three separate calls on the property reference — `lo_entity_type->get_primitive_property( '<field>' )->set_edm_type( /iwbep/if_v4_med_element=>gcs_edm_data_types-decimal )`, then `...->set_precision( 15 )`, then `...->set_scale( 3 )`. (`set_edm_type`/`set_precision`/`set_scale` return void — they cannot be chained `->` like a function call. Use `...-boolean` for `abap_bool`/flags where the auto-mapping did not guess.)
- **[info]** Navigation property: `lo_entity_type->create_navigation_property( iv_internal_name )` → `->set_target_entity_type_name( )`, `->set_target_multiplicity( /iwbep/if_v4_med_element=>gcs_med_nav_multiplicity-to_many_optional )`, `->set_edm_name( )`; binding to the target set — `lo_entity_set->add_navigation_prop_binding( iv_navigation_property_path, iv_target_entity_set )`.
- **[info]** Data in/out: `io_request->get_busi_data( IMPORTING es_busi_data = ... )`, `get_key_data( )`, `get_selected_properties( )`, `get_filter_props_with_ranges( )`/`get_filter_ranges_for_prop( )`, `get_expand_tree_list( )`, `get_parameter_data( )` (for an action); output — `io_response->set_busi_data( )`, `set_count( )`, `set_target_key_data( )`.
- **[info]** Complex (structured) types: `io_model->create_complex_type_by_struct( iv_complex_type_name, is_structure )`, `create_complex_property( ... )`, `set_complex_type( ... )`, `get_primitive_properties( )` — nested structures in the EDMX, used for deep/structured payloads.
- **[info]** Navigation/deep read — `io_request->get_navigation_path( )` and the todo flag `process-deep_busi_data`; deep payload access via `/iwbep/cl_v4_request_info_pro`/`/iwbep/cl_v4_response_info_pro` (`get_base_request_info( )->get_service_group_id( )`/`get_busi_data( )`, `get_base_response_info( )->get_busi_data_pro_sub_tree( )`).
- **[info]** Deep-insert: `io_request->get_data_description_tree_list( IMPORTING et_data_desc_root_node = lt_stack )`, walk via `get_children( )`, on each node `get_todos( )` + `set_is_done( )`.
- **[info]** `$batch`/changeset in v4 — via the interface `/IWBEP/IF_V4_DP_BATCH`, not `CHANGESET_BEGIN/PROCESS` from v2.
- **[info]** Registering a v4 service — `/IWBEP/V4_ADMIN*` (registration) and `/IWFND/V4_ADMIN*` (publication). Do not use `/IWBEP/V4_MAP` — it does not exist (verified on a live system).
